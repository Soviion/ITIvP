# Система управления клиникой

Курсовой проект: REST API (Node.js, Express, Sequelize, PostgreSQL) и клиент на React.
Ветка **`25`** — лабораторная работа №5: интеграция React-клиента с REST API.

```
.
├── server.js, routes/, controllers/, models/, ...   REST API (лабораторные 1–3)
├── migrations/, seeders/                            схема БД и демонстрационные данные
└── client/                                          React-клиент (лабораторные 4–5)
```

## Запуск

Нужны Node.js 20+ и доступная база PostgreSQL.

### 1. Сервер (порт 3000)

В корне репозитория создайте файл `.env` (в git он не попадает) со значениями:

| Переменная | Что это |
| --- | --- |
| `DATABASE_URL` | строка подключения к PostgreSQL |
| `DB_SSL` | `true`, если сервер БД требует SSL, иначе `false` |
| `PORT` | порт API, по умолчанию `3000` |
| `JWT_SECRET` | секрет подписи токенов, не короче 32 символов |
| `JWT_EXPIRES_IN` | срок жизни токена, например `1h` |
| `TOTP_ENCRYPTION_KEY` | 64 hex-символа, ключ шифрования секретов Google Authenticator |
| `TOTP_ISSUER` | название приложения в Google Authenticator |
| `APP_BASE_URL` | адрес сервера для ссылки в письме, `http://localhost:3000` |
| `SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASS` | почта для писем с подтверждением (Gmail, пароль приложения) |
| `CLIENT_ORIGIN` | необязательно: адрес клиента для CORS, по умолчанию `http://localhost:5173` |

```bash
npm install
npm run db:migrate     # создать таблицы
npm run db:seed        # демонстрационные данные (врачи, пациенты, записи)
npm run dev            # http://localhost:3000
```

### 2. Клиент (порт 5173)

```bash
cd client
npm install
npm run dev            # http://localhost:5173
```

Адрес API задаётся в `client/.env` (`VITE_API_URL=http://localhost:3000`).

### 3. Как проверить

1. Откройте http://localhost:5173. Без входа видны врачи и свободные талоны: выберите врача, дату, время и нажмите «Записаться».
2. Регистрация (3 шага на одной странице): почта и 6-значный код из письма → анкета пациента → пароль. После создания пароля откроется главная с окном входа справа.
3. После входа в шапке видны имя, кружок с меню (медицинская карта, мои талоны, история болезни, настройки) и кнопка «Выйти».
4. «Настройки» → «Google Authenticator»: QR-код, ввод кода, при следующем входе код потребуется. Там же смена почты (по коду) и пароля.
- Вход возможен по почте или по номеру телефона. Телефон везде в строгом формате `+375(44)4444444`: маска с префиксом показывается всегда, лишние цифры ввести нельзя.
- У пациента не больше 4 активных талонов. Талон можно перенести на другое свободное время и изменить его описание («Мои талоны» → «Изменить»).
- На главной справа «Доска почёта»: три случайных врача (меняются при каждом обновлении страницы), кнопка «Подробнее» открывает профиль врача. Профили статические и лежат в `client/src/data/doctorProfiles.js`. Фотографии врачей (`client/public/doctors`) сгенерированы нейросетью StyleGAN, источник — thispersondoesnotexist.com; изображённых людей не существует.
- Из формы записи кнопка «Подробнее о враче» ведёт в профиль; вернуться можно по хлебным крошкам, выбранные врач, дата и время сохраняются.

6. Сотрудник регистратуры (аккаунт с ролью `staff`) видит в шапке пункт «Регистратура»: там полный список записей, оптимистичные операции и retry из лабораторной №5. Остановите сервер и повторите действие, чтобы увидеть повторные попытки и откат.

#### Роли и миграции

В базе добавлена роль пользователя (`users.role`). После `npm run db:migrate` все **существующие** аккаунты становятся сотрудниками (`staff`), новые, зарегистрированные пациентами, получают `patient`. Пациенту недоступны общие списки `/patients` и `/appointments` (ответ 403). Дать роль сотрудника можно запросом:

```sql
UPDATE users SET role = 'staff' WHERE email = 'name@mail.by';
```

Старые маршруты регистрации по ссылке (`/auth/register`, `/auth/verify-email`, `/auth/resend-verification`) заменены на `/auth/register/start`, `/auth/register/verify`, `/auth/register/complete`.

## Что реализовано в лабораторной работе №5

- **CORS** на сервере (`server.js`, пакет `cors`): клиент на другом порту получает доступ к API, разрешён заголовок `Authorization`.
- **`client/src/api.js`**: экземпляр axios, интерцептор запроса добавляет `Authorization: Bearer <JWT>` из `localStorage`, функции `fetchAppointments`, `addAppointment`, `updateAppointment`, `patchAppointment`, `deleteAppointment`.
- **Список с состояниями**: спиннер при загрузке, сообщение об ошибке и кнопка «Повторить», загрузка один раз при открытии (`useEffect`) с отменой запроса через `AbortController`.
- **Оптимистичные обновления** (`client/src/hooks/useAppointments.js`): добавление (временный `id = Date.now()`, замена на настоящий, откат при ошибке), удаление и редактирование (откат при ошибке), уведомления об ошибках.
- **Улучшение «Повтор запроса при ошибке (retry)»**: до 3 попыток с задержкой 1 с и 2 с, индикатор «попытка N из 3».
- **JWT**: токен сохраняется в `localStorage` после входа и подставляется автоматически; при ответе 401 пользователь возвращается на экран входа.
- Личный кабинет пациента: регистрация с подтверждением почты кодом, запись на свободные талоны, медицинская карта, мои талоны (активные и архив), настройки (почта, пароль, Google Authenticator). Регистраторская часть с CRUD записей находится по адресу `/staff`.
